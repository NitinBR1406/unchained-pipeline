# Computer-use capability discovery V01

The installed unified-computer-use MCP is callable in the current desktop task. Two successful `cua.getState` calls returned inventory; the second emitted the sanitized machine-readable result captured in CAPABILITY_DISCOVERY.json. No app selection, launch, navigation, click, typing, render, export or publication was performed. Unrelated app names and browser content are deliberately omitted.

Documented capabilities include accessibility/screenshot observation, native app and browser interaction, and browser navigation. Only inventory discovery was tested. Resolve was not listed; installation and Resolve-specific operation remain unknown. This is evidence for a potential GUI-stage adapter, not acceptance of a production adapter.

The CLI configuration lists enabled computer-use and cua_repl servers. This does not establish access from the controller child (which uses isolated read-only execution and ignores user configuration). No child tool invocation or controller integration was performed. The proven durable Codex dispatcher remains unchanged.

Before a Resolve stage can be accepted, discover its actual API/CLI interface, then if necessary test GUI observation on an explicitly disposable workload. Require exclusive desktop ownership, preconditions, bounded actions, output validation and persisted artifact receipts. After an ambiguous action, reconcile output rather than blindly retry. These are proposed acceptance requirements, not implemented capabilities.

This append-only evidence supplement does not change Master State V10 or promote production readiness. No frozen P0-E0–E3 files changed.
